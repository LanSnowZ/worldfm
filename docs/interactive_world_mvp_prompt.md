# 受限版交互式世界探索 MVP Prompt

```text
你现在要在这个仓库里实现一个“受限版交互式世界探索” MVP。请先完整阅读仓库，再动手实现。不要先空谈方案，直接基于现有代码落地。

项目根目录:
`/home/lsn/workspace/worldfm`

核心背景:
这个仓库当前不是完整的可游玩世界模型，也不是游戏引擎。它当前更像“单图 -> 场景代理 -> 指定位姿新视角生成”的推理流水线。
主流程在这些文件里:
- `run_pipeline.py`
- `modules/panogen.py`
- `modules/pano_postprocess.py`
- `modules/point_renderer.py`
- `modules/depth_selector.py`
- `modules/worldfm_infer.py`
- `default.yaml`

你必须基于现有算法边界实现，不要误做成“无限扩展世界”或“真正实时 3D 游戏”。

一、我真正要的功能
实现一个本地可运行的 Web 前端 + Python 后端，支持以下流程:

1. 用户上传一张起始图片
2. 点击“生成场景”
3. 后端基于现有 WorldFM 流程完成场景初始化
4. 初始化完成后，前端显示当前视角图像
5. 用户可以进行受限交互:
   - `W / S`: 前进 / 后退
   - `A / D`: 左移 / 右移
   - `ArrowLeft / ArrowRight`: 左右转头
   - `ArrowUp / ArrowDown`: 上下抬头/低头
6. 每次用户移动或转头后，后端生成新的视角图像并返回前端
7. 前端刷新显示最新结果，形成“低速探索”的体验

二、必须遵守的产品边界
这部分非常重要，不能偏题:

1. 起始输入只考虑“图片”
   - 不做 prompt 输入
   - 不做 text-to-world
   - 不接入额外的 prompt UI

2. 这是“受限版交互式探索”
   - 允许小范围平移
   - 允许低速转头
   - 不追求游戏级实时
   - 不追求 30/60 FPS 连续渲染
   - 不做无限世界扩展
   - 不做边走边更新长期世界记忆
   - 不做真正的 3D mesh 游戏漫游

3. 必须承认现有算法限制
   - 现有主流程是先从初始输入构建固定的 panorama/depth/pointcloud/condition data
   - 后续每一帧只是基于固定场景代理做重投影 + WorldFM 推理
   - 因此它更适合“原地转头 + 小范围挪动”，不适合大范围行走

4. 一定要做安全约束
   - 限制最大移动半径
   - 限制每次移动步长
   - 限制 pitch 范围
   - 限制请求频率
   - 一次只允许一个推理请求在跑
   - 超出探索边界时给出明确提示，不要继续错误生成

三、你必须复用的现有流程
请不要重写算法。必须尽量复用现有主流程中的逻辑。

正确思路应该是:

1. 场景初始化阶段，只执行一次:
   - Step 1: 图片 -> panorama
   - Step 2: panorama -> depth / point cloud / conditions
   - Step 3 init: renderer + condition db
   - Step 4 init: WorldFM service

2. 探索阶段，每次只执行:
   - `step3_render_one(...)`
   - `step4_infer_one(...)`

3. 必须把这些初始化结果缓存到服务端 session 中，避免每次按键都重新跑 Step 1/2/3 init/4 init

四、技术要求
请直接实现一个最小但可用的 Web Demo。

建议技术路线:
- 后端: Python，优先轻量方案，例如 FastAPI 或类似轻量 Web 服务
- 前端: 原生 HTML/CSS/JS 即可
- 不要引入重型 Node/React 构建链，除非绝对必要
- 不要修改 submodules，除非确实无法避免
- 优先在主仓库内新增最少量文件完成功能

五、具体实现要求
请实现以下能力:

1. 页面功能
   - 图片上传
   - “生成场景”按钮
   - 当前状态显示: 未开始 / 生成中 / 可探索 / 生成下一帧中 / 超出边界 / 出错
   - 图像预览区域
   - 控制说明区域

2. 会话管理
   - 每个上传任务对应一个 session
   - 服务端保存:
     - panorama / postprocess result
     - renderer
     - condition db
     - WorldFM service
     - 当前相机位姿
   - 刷新或重复请求时不要混乱
   - 至少支持单用户本地演示稳定运行

3. 相机控制
   - 初始位姿从一个合理默认值开始
   - `W/S/A/D` 控制小范围平移
   - 方向键控制 yaw/pitch
   - pitch 需要夹紧
   - 平移半径需要限制
   - 建议把这些参数做成集中配置，便于后续微调

4. 交互节流
   - 不要在浏览器键盘连发时无限堆积请求
   - 同一 session 一次只允许一个推理任务
   - 如果前一帧还没完成，新的移动请求要么丢弃，要么只保留最后一个
   - 前端在等待下一帧时继续显示上一帧，并显示“生成中”

5. 错误处理
   - 图片非法
   - 模型未准备好
   - session 失效
   - 超出探索范围
   - 推理失败
   都要有清晰提示

六、推荐的交互参数
为了适配当前算法能力，请使用保守默认值，且做成可配置:
- 平移步长: 小步，例如 0.05 到 0.15
- 转头步长: 小角度，例如 3 到 8 度
- 最大探索半径: 小范围，例如 0.5 到 1.0
- pitch 限制: 例如 [-45°, 45°]
- 请求节流: 低频，不追求持续高帧率
```
